Decisions I made on your behalf
Rates and yields: anything quoted for an instrument (prices, exchange rates, benchmark yields, SOFR, index levels) is a market observation. Periodic statistics that get revised (CPI, GDP) are economic observations.
Deduplication: market observations and candles are immutable, so a repeat writes nothing and a differing value is logged as a warning. Economic revisions are stored as a new row beside the old one.
Keys: entity tables use UUIDs. The two hypertables use a natural composite key including the time column, with no surrogate id.
Instrument management: a version-controlled seed file is the source of truth, and the API stays read-only. Write endpoints move to Phase 12, after authentication exists.
Manual collection: POST /collectors/{job}/run, protected by an ADMIN_API_KEY header check and disabled when the key is unset.
Binance stays in Phase 8: until then crypto comes from CoinGecko at 5 minutes (about 8,640 of its 10,000 monthly calls). The 1-minute target applies once Binance arrives.
Twelve Data budget: the default set is 10 stocks/ETFs plus 5 forex pairs at 15 minutes, which uses 740 of 800 daily credits. Stocks are polled only during trading hours.
Dropped or deferred scope: EURIBOR is replaced by €STR, PMI is out of scope, and individual bond data is deferred until a provider supplies it. Stock market cap and ETF NAV/AUM are marked plan-dependent.
Stack specifics: async SQLAlchemy 2.x with asyncpg, APScheduler 3.x, pydantic-settings, and standard logging with a JSON formatter.
httpx: it stays for provider calls. The test client may move to httpx2 when the pinned Starlette requires it.
Test database: integration tests run against a separate database on the Compose db service.

Decisions I made
Seed format is TOML: Python reads it from the standard library, so it needs no new dependency.
Seed runs in the migrate service, not inside the backend: an invalid file stops the startup with a clear log line, and the backend never starts half-configured.
Removed seed entries are not deleted: stored history refers to them, so you disable them with enabled = false.
Enumerations are text with a check constraint, not PostgreSQL enum types, so adding a value is an ordinary migration.
The seed file ships nearly empty: it has two exchanges (Nasdaq and NYSE) and no providers or instruments. Those arrive with each provider in Phase 4.
One enumeration added to the PRD: indicator frequency (daily to annual), which the model needed.
Limitations
Candle interval is free text: nothing yet stops one provider writing 1d and another 1day. Phase 3 normalization needs to fix the allowed values.
Collector execution and provider health have tables but no repositories: they come with the phases that write them (3 and 5).
Performance targets are untested: the PRD's query-time targets haven't been measured, since there is no realistic data volume yet.
Continuous integration is still unticked from Phase 1: the workflow has never run because this isn't a git repository.

Phase 3 (Provider Integration Framework) is implemented and verified: all 16 roadmap tasks are ticked, 158 tests pass and Ruff is clean. No real provider exists yet, so nothing is collected; that starts in Phase 4.

A Phase 2 bug found and fixed along the way
The check constraints from Phase 2 had been created with a doubled prefix, such as ck_instrument_ck_instrument_asset_type. Alembic applied the naming convention on top of the names I had already written out, and my tests matched by substring, so they missed it.

Fix: I corrected migrations 0002 and 0003 and added a test that compares constraint names exactly.
Database reset: to apply the corrected migrations I rolled the application database back to revision 0001 and re-migrated it. It held only the two seeded exchanges, which the seed recreated. I also dropped and recreated the test database.
What was verified
Tests: 158 pass, 36 of them against the real TimescaleDB test database. Provider tests use a mock transport and a fake clock, so nothing touches the network or sleeps.
Acceptance criteria:
a provider failure is contained and recorded without raising;
malformed responses are rejected;
every attempt, including retries, takes rate-limit credits;
an adapter's output goes through ingestion into the database.
Credential safety: a test confirms the API key never appears in error messages or log records, including when the underlying error text contains it.
Running stack: the application database is at revision 0003, all services are healthy, and the built image imports the new modules.
What was added
Provider base and factory: adapters subclass the base in base.py, and factory.py builds them from their database row.
HTTP client: http.py handles authentication, timeouts, retries with exponential backoff, Retry-After, and decoding numbers as Decimal.
Rate limiter: rate_limit.py enforces every configured limit per provider over a rolling window.
Normalized schemas: Quote, Candle and IndicatorValue in normalized.py.
Ingestion and validation: ingestion.py resolves provider symbols to instruments, rejects invalid values with a logged reason, and stores the rest.
Provider health: provider_health.py records success and failure; three consecutive failures mark a provider down.
Docs: docs/providers/README.md is the integration checklist for Phase 4, and docs/architecture.md has a new framework section.
Decisions I made
Provider settings live in the seed file and are strictly validated. A mistyped setting, or a base_url that isn't https, stops the startup.
Credentials are referenced by environment variable name only, and the name must end in _API_KEY or _TOKEN, so configuration can't be used to send another secret (such as the database password) to a provider.
An exhausted quota fails fast. A request waits at most 60 seconds for capacity by default, then is refused, so a used-up daily or monthly quota doesn't block.
Candle intervals are now a fixed set (1min to 1month), enforced in the schema and by a database constraint. This closes the free-text limitation from Phase 2.
New dependencies: httpx 0.28.1 and python-dotenv 1.2.4 are pinned (the latter was already installed transitively).
Limitations
Rate-limit counts are in memory: they restart from zero when the backend restarts, so a restart mid-day could overshoot a daily or monthly quota. The startup budget check in Phase 5 is what keeps planned usage inside those quotas; I noted this in the PRD.
The framework isn't wired into the running app yet: nothing builds a provider factory at startup, because nothing calls a provider until Phases 4 and 5.
Continuous integration is still unticked from Phase 1: the workflow has never run because this isn't a git repository.
